# Security Policy

## Supported versions

| Version | Supported |
|---|---|
| Latest tagged release (`v*`) | ✅ yes |
| Unreleased `main` | best effort |

The factory (`composer.json`) and the platform (`platform/package.json`) carry
independent version numbers; both are released from tagged commits.

## Reporting a vulnerability

**Do not open a public issue for security problems.** Even using GitHub's
private vulnerability reporting is fine, but the preferred channel is
direct, end-to-end encrypted:

- **Email:** `security@ansariai.ir` — with the PGP key published on
  [ansariai.ir](https://ansariai.ir) (if a key is not yet published,
  start the conversation via GitHub's private vulnerability report or a
  Telegram DM to [@ansariaiadmin](https://t.me/ansariaiadmin) with the word
  *SECURITY* and the maintainer will switch to an encrypted channel).

Please include:

1. Affected component (factory / platform / generated-plugin behaviour).
2. Affected version(s) — the tag or commit hash.
3. A minimal reproduction (commands or a short script).
4. Impact assessment (what a remote or local attacker can do).
5. A suggested fix, if you have one.

## What we ask in return

- Give the maintainer **at least 30 days** to ship a fix before public
  disclosure (90 days for complex supply-chain issues).
- Don't test the vulnerability against third parties' deployments.
- Credit is given in the release notes unless you ask to stay anonymous.

## Scope

In scope: the factory pipeline, the license/payment/auth surface of the
platform, and behaviour the factory *guarantees* in generated plugins
(nonces, capability checks, sanitization, prepared SQL — see the Security
section of the README).

Out of scope: vulnerabilities in third-party services (ZarinPal, Stripe,
Resend, LLM providers), cloud provider configurations not shipped in this
repo, and the WordPress/WooCommerce core itself.

## Process & response targets

| Step | Target |
|---|---|
| Acknowledgement | 48 hours |
| Triage + severity | 7 days |
| Fix shipped (tag + release) | 30 days typical, 90 days hard ceiling |
| Public disclosure | only after the fix is released (or with your consent) |

## Self-hosting checklist (for platform operators)

The platform fails fast on missing secrets, but production operators should
also verify:

- `SESSION_SECRET` ≥ 32 random chars and `ENCRYPTION_KEY` ≥ 16 random chars
  (generated by `install.sh`; regenerate both if you suspect exposure —
  rotating `ENCRYPTION_KEY` invalidates stored provider keys, re-enter them).
- Terminate TLS at the edge (nginx template in `platform/nginx/`) and set
  `TRUST_PROXY=true` **only** when the app is not directly reachable.
- Keep `ALLOWED_ORIGINS` explicit for multi-domain deployments.
- Run `docker compose exec -T platform node scripts/migrate.mjs` on every
  update (idempotent).
- Back up the `pgdata` volume regularly (`./backup.sh` does this).
