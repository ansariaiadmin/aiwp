### English

Every line of both products was read (≈47k LOC + ≈2.5k lines of docs); every claim in
this report was measured by actually running the code, not by reading it. Result:
**47 findings** — 3 high (directly broke the product), 12 medium (security/perf),
the rest low/docs. **28 are fixed and regression-pinned in this PR; the remaining 19
are listed in «Remaining work» with exact instructions.** The table above lists the
important ones; the complete register is in §4.

**Why it matters:** three findings were «the product does not do what the README
promises» class — a free-plugin spec could not validate, the README quickstart sample
failed the project's own schema, and the security bullet list advertised features that
were not implemented. Those are trust defects, not code defects, and they are now
corrected with measured evidence instead of marketing claims.

## ۳ / Security model review (design-level verdicts)

**Sound designs confirmed** (kept as-is, documented so future audits don't re-litigate):

- Sessions: short-lived signed JWT (HS256, 7d) **+ server-side session row with
  SHA-256 token hash** → revocable; proxy does signature-only gating, API routes do the
  DB check. Stale role in the JWT is bounded by the DB check on every mutating route.
- Passwords: Argon2id (19 MiB / t=3 / p=1, OWASP parameters) via hash-wasm (no native
  addon — correct call for the Docker matrix).
- TOTP: RFC 6238 with ±1 window, constant-time compare, no third-party OTP lib.
- CSRF: `SameSite=lax` + same-origin Origin verification in the proxy for every
  mutating cookie-authenticated route; `/api/license/*` deliberately excluded
  (cross-origin by design, keyed by license, rate-limited per IP).
- Payments: license provision **only** after `gateway.verify()` confirms the
  transaction server-to-server, with server-side amount match and an idempotent
  compare-and-set PAID transition (replayed callbacks cannot mint a second key).
- Secrets: AES-256-GCM at rest with per-value IV; masked in all API responses;
  ENCRYPTION_KEY rotation failure degrades to «unset», not 500s.
- Origin/IP trust: documented trust model for `HOSTNAME=0.0.0.0` deployments.

**Defects found & fixed** — see §4 register (F-HTTP-1, F-LICSV-*, F-RAG-1, F-CSV-1, F-PAY-1).

**Noted, accepted with rationale** (low):

- F-PLAT-1: CSP uses `script-src 'self' 'unsafe-inline'` — required for inline scripts
  emitted by the current page code; migrating to nonces is a multi-page refactor.
- F-PLAT-4: login route distinguishes SUSPENDED / PENDING_VERIFICATION / bad-password
  messages → mild account-state oracle; standard trade-off, documented.
- F-PLAT-5: JWT role is not re-read per request (DB role is, on every API route).
