# نصب و راه‌اندازی روی لینوکس

راحت‌ترین راه: **دابل‌کلیک روی `AiWp.desktop`**.

اگر دابل‌کلیک کار نکرد، در ترمینال:

```bash
./start-aiwp.sh
```

---

## بار اول چه اتفاقی می‌افتد

۱. **Node.js** — اگر نسخه‌ی ۲۲ یا بالاتر روی سیستم باشد، از همان استفاده می‌شود.
   وگرنه یک نسخه‌ی خصوصی داخل `.runtime/node/` دانلود و باز می‌شود.
   **بدون sudo و بدون نصب سیستمی.**

۲. **وابستگی‌های npm** — با `npm ci` نصب می‌شوند (چند دقیقه).

۳. **دیتابیس** — PGlite، یعنی PostgreSQL کامپایل‌شده به WebAssembly که داخل
   خودِ پروسه اجرا می‌شود. **نیازی به نصب PostgreSQL نیست.**
   داده‌ها در `.runtime/pgdata/` ذخیره می‌شوند و بعد از ریستارت باقی می‌مانند.

۴. **Build** — اپلیکیشن ساخته می‌شود (حدود یک دقیقه).

۵. **حساب مدیر** — فقط اگر هیچ حساب مدیری در دیتابیس نباشد ساخته می‌شود.

۶. مرورگر باز می‌شود.

## بارهای بعد

هیچ دانلودی انجام نمی‌شود. هر مرحله یک marker در `.runtime/markers/` دارد و
اگر تغییری ندیده باشد رد می‌شود:

| مرحله | کی دوباره اجرا می‌شود |
|---|---|
| Node.js | هرگز (بعد از بار اول) |
| npm ci | فقط اگر `package-lock.json` عوض شود |
| build | فقط اگر فایلی در `src/`، `drizzle/` یا `next.config.ts` عوض شود |
| migrations | هر بار (idempotent و سریع) |
| حساب مدیر | فقط اگر هیچ مدیری وجود نداشته باشد |

**رمز عبورتان هرگز بازنشانی نمی‌شود.** لانچر قبل از seed از خودِ دیتابیس
می‌پرسد که آیا مدیری هست یا نه؛ چون `seed-admin.mjs` رمز را بازنویسی می‌کند،
اجرای بی‌قید و شرط آن رمز تغییر یافته‌ی شما را به حالت پیش‌فرض برمی‌گرداند.

## فایل‌ها

| فایل | کار |
|---|---|
| `AiWp.desktop` | آیکون دابل‌کلیک |
| `launch-terminal.sh` | یک پنجره‌ی ترمینال باز می‌کند تا پیشرفت را ببینید |
| `start-aiwp.sh` | خودِ لانچر |
| `stop-aiwp.sh` | توقف اپ و دیتابیس |
| `.runtime/` | همه‌چیز دانلود/ساخته‌شده + داده‌های دیتابیس + لاگ‌ها |

`.runtime/` در `.gitignore` است و هیچ‌وقت commit نمی‌شود.

## اگر دابل‌کلیک کار نکرد

گنوم در اوبونتو به فایل‌های `.desktop` اجازه‌ی اجرا نمی‌دهد مگر اینکه اعتماد
شده باشند. یک بار این را انجام دهید:

```bash
chmod +x AiWp.desktop launch-terminal.sh start-aiwp.sh stop-aiwp.sh
gio set AiWp.desktop metadata::trusted true
```

سپس روی فایل راست‌کلیک → **Allow Launching** (یا **Properties → Permissions →
Allow executing file as program**).

اگر باز هم نشد، مستقیم اجرا کنید:

```bash
./start-aiwp.sh
```

## تنظیمات

همه با متغیر محیطی، بدون ویرایش فایل:

```bash
AIWP_PORT=8080 ./start-aiwp.sh              # پورت اپ (پیش‌فرض 3000)
AIWP_DB_PORT=5433 ./start-aiwp.sh           # پورت دیتابیس (پیش‌فرض 5432)
AIWP_ADMIN_EMAIL=me@example.com ./start-aiwp.sh
AIWP_ADMIN_PASSWORD='...' ./start-aiwp.sh   # فقط در اولین اجرا اثر دارد
AIWP_NODE_VERSION=v22.22.3 ./start-aiwp.sh  # نسخه‌ی Node قابل دانلود
```

## عیب‌یابی

لاگ‌ها در `.runtime/logs/` هستند:

| فایل | محتوا |
|---|---|
| `npm-install.log` | نصب وابستگی‌ها |
| `build.log` | ساخت اپلیکیشن |
| `migrate.log` | مهاجرت‌های دیتابیس |
| `db.log` | سرور PGlite |
| `app.log` | خودِ اپلیکیشن |

**«port 3000 is busy»** — یا AiWp از قبل در حال اجراست، یا برنامه‌ی دیگری آن
پورت را گرفته. با `AIWP_PORT=8080 ./start-aiwp.sh` پورت را عوض کنید.

**دانلود Node ناموفق بود** — یعنی دسترسی به `nodejs.org` ندارید. Node ۲۲ را
خودتان نصب کنید (`sudo apt install nodejs npm` یا از nodesource)؛ لانچر
نسخه‌ی سیستم را تشخیص می‌دهد و دانلود نمی‌کند.

**می‌خواهم از صفر شروع کنم** — `./stop-aiwp.sh && rm -rf .runtime` و دوباره
اجرا کنید. این کار **همه‌ی داده‌ها را پاک می‌کند**.

## ابزارهای PHP (کارخانه‌ی پلاگین)

اپلیکیشن وب به PHP نیاز ندارد. برای ساخت پلاگین:

```bash
sudo apt install php-cli php-zip
composer build -- spec/examples/store-health.json
```

در محیط‌هایی که نصب PHP ممکن نیست، یک اجرای‌کننده‌ی WebAssembly در
`tools/php-wasm/` هست که همان فایل‌های PHP را اجرا می‌کند:

```bash
cd tools/php-wasm && npm install
npm run build     # validate → compose → syntax check → lint → zip
npm test          # تست‌های کارخانه
```

این فقط برای **تأیید** است؛ مسیر واقعی build همان `php` بومی است.

### تست اتصال پلاگین ↔ پلتفرم

این تست قرارداد بین دو نیمه را می‌سنجد: پلاگینِ ساخته‌شده و پلتفرمی که
باید لایسنسش کند.

```bash
# ۱. پلتفرم را بالا بیاورید و یک کلید لایسنس واقعی بسازید (از /admin/orders)
# ۲. سپس:
cd tools/php-wasm
AIWP_LICENSE_KEY='XXXX-XXXX-XXXX-XXXX' \
AIWP_PLATFORM_URL='http://127.0.0.1:3000' \
  npm run test:integration
```

چگونگی کار: PHP وب‌اسم سوکت خروجی ندارد، پس هارنس سه مرحله دارد —

1. `LicenseClient` واقعی پلاگین اجرا می‌شود و درخواست‌هایش **ضبط** می‌شوند.
2. هارنس همان درخواست‌ها را به پلتفرم زنده می‌فرستد. فقط origin عوض می‌شود؛
   **مسیر دست‌نخورده می‌ماند** چون مسیر همان چیزی است که تست می‌شود
   (هاست تنظیمات استقرار است، نه قرارداد).
3. پاسخ‌های واقعی به خودِ پلاگین برگردانده می‌شود تا کد تجزیه‌ی پاسخِ خودش
   روی داده‌ی واقعی اجرا شود.

اگر کسی `/api/v1/license/*` را جابه‌جا کند یا `LicenseClient` مسیر دیگری
بسازد، این تست قرمز می‌شود.
